# Changelog

Notable changes to StrataKB. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Knowledge layers with per-layer chunking, metadata schema and routing patterns.
- Layer presets: a YAML file describes a layer and its source folders; `strata_apply_preset` and `scripts/apply_preset.py` build or rebuild the layer, with a dry-run mode that needs no database.
- Example presets for SEPA payments and ISO 20022 messaging, with a sample reason code list and download instructions.
- Ingestion of PDF, DOCX, Markdown, HTML, CSV, JSON, XML/XSD and OpenAPI/AsyncAPI YAML.
- Hybrid retrieval (pgvector HNSW plus full-text search, fused with RRF), cross-encoder reranking and a per-layer-invalidated query cache.
- `strata_ask`: optional query rewriting, built from the layers' own descriptions, with parallel multi-query search and source citations.
- Learning system: interaction tracking, implicit signals (rephrasing, layer switches, follow-ups), synonym mining and explicit feedback.
- Viewer, operator and admin roles on every tool, an append-only audit log, and read-only SQL tools.
- Masking of IBANs and card numbers in logs, and scrubbing of IBANs, BICs and account numbers from stored queries.
- Local embeddings (`all-mpnet-base-v2`) by default, OpenAI embeddings optional, and in-place re-embedding of a layer.
- Docker Compose setup that creates all schemas, including the learning schema, on first start.
- `strata_readonly` database role (`db/03_readonly_role.sql`) and the `READONLY_DATABASE_URL` setting for the SQL tools.
- `strata_search` and `strata_ask` return an `interaction_id` for `strata_feedback`; `strata_ask` also reports `auto_detected_layers`.
- The promoter learns query rewrites from asks marked helpful and from rephrased questions that then got a high-confidence result, and layer affinities from `correct_layer` feedback and layer switches.
- `stratakb add <folder>` turns a folder into a layer in one step: it picks the files (git-aware, honouring `.gitignore` and a root `.strataignore`), skips secrets, build files, code and unsupported formats, asks before a broad path or a large run (`--allow-broad`, `--yes`), shows progress and prints a summary, or a JSON report with `--json`. Running it again syncs the folder. `stratakb` alone or `stratakb serve` still starts the server.
- Layers record their origin (`manual`, `preset:<name>` or `folder`), owner and root folder; one folder belongs to at most one layer.
- Plain-text documents: `.txt`, `.rst` and `.adoc`.
- A Python PEPs example preset (`examples/peps/`), fetched with a sparse git clone and never committed.
- `EMBEDDING_BASE_URL` and `EMBEDDING_API_KEY`: embed through any OpenAI-compatible server, such as Ollama, LM Studio or vLLM. Vectors whose length differs from `EMBEDDING_DIMENSIONS` are refused with a message naming the setting.
- `QUERY_REWRITE_PROVIDER=openai_compatible` with `QUERY_REWRITE_BASE_URL`, `QUERY_REWRITE_MODEL` and `QUERY_REWRITE_API_KEY`: rewrite questions through a local or self-hosted chat model. The reply parser accepts the first JSON array of strings anywhere in the reply.
- `STRATA_LOCAL_ONLY`: the server refuses to start while any setting would send content to a host that is not loopback, keeps Hugging Face offline, and `strata_admin_health` lists the active outbound providers by host and setting name. The README gains a "Where your data goes" section.
- At startup the server checks, in the background, that the embedding server lists the configured model and that the vector column matches `EMBEDDING_DIMENSIONS`; `strata_admin_health` reports both under `embedding`.
- Ingestion flags PDFs that look scanned (`files_flagged`, reason `probably_scanned`).
- Numbered schema migrations, recorded in `strata_core.schema_migrations`. The server and `stratakb add` build an empty database from the schema files shipped in the package, and bring an existing one up to date.
- A routed search (no layers given) that returns fewer results than asked for, or only low-confidence ones, runs again across all layers. `strata_search` and `strata_ask` report `routing_fallback` with the reason (`insufficient_results` or `low_confidence`); layers you name are never broadened. Results carry the query/chunk cosine `similarity` next to the fused rank score.
- `HYBRID_KEYWORD_SLOTS` (default 1): hybrid search keeps places for the best full-text matches, so an exact term or identifier the embedding misses (a reason code, a message name) still reaches the results. The `hybrid_search_complete` log reports `keyword_only_results`.
- Each ingested document's extracted text is stored once per version in the new `strata_vectors.documents` table (migration `07_documents.sql`), and every chunk records where it sits in that text (`char_start`, `char_end`). A document's version goes up only when its text changes; old versions are removed once no chunk uses them. Chunks ingested before this change have no offsets and stay searchable. Backups made with `scripts/backup_restore.py` do not include the stored text yet.
- `stratakb db up` starts a local PostgreSQL with pgvector in Docker (container `stratakb-db`, volume `stratakb-data`, `127.0.0.1:5433` or `--port`), waits until it accepts connections and builds the schema; it needs no checkout of the repository. Run again, it leaves a running database alone and starts a stopped one with its data. `stratakb db down` stops it and keeps the volume. The Quick start uses it; `docker compose` stays for development. When `stratakb add` or the server cannot reach the database, the message ends with "Run `stratakb db up` to start a local database."
- `vector_store.re_embed_all_layers()` re-embeds every layer in one transaction and resizes the shared vector column once when the dimensions change.
- Layers have an `answer_mode`, `grounded` (default) or `extractive` (migration `12_answer_mode.sql`). Presets set it with an `answer_mode` key, and layer listings show it.
- `strata_apply_preset` reports the layer settings that changed (`layer_changes`), and its dry run the settings that would change (`layer_check`).
- `strata_search` returns a `confidence` (level, top score, relevant sources, basis `similarity`), in the same shape as `strata_ask`; the learning tracker stores that value instead of judging the search again.
- `vector_store.re_embed_all_layers()` takes `locked_timeout` (default 600 s per statement) for the locked phase, which before ran under the pool's 30 s limit.
- More CI checks: an end-to-end job with the real embedding and reranking models, a stdio smoke test, ruff and LF line endings on changed files, a repository-rules check (`scripts/check_repo_rules.py`), dependency review, Mermaid and offline link checks on Markdown changes, and a weekly external-link check of the repository and the wiki. The test database now starts empty and is built by the server's own migrations. See "What CI checks" in CONTRIBUTING.md.
- Ingestion reports a file that cannot be read (locked, no permission) as failed with reason `read_error`, instead of `parse_error`; every failed file in `errors` carries its reason.
- `strata_apply_preset` with `dry_run=true` reports `would_claim` for a layer with no recorded origin that already matches the preset.
- Markdown: setext headings (`===`, `---` underlines) and ATX headings indented by up to three spaces.
- `strata_feedback` and `strata_reset_learning` write audit entries: feedback names the user, the interaction, whether it was helpful and which extra signals were given (never their text); a reset names its scope, one layer or all.
- The `strata_apply_preset` audit entry names the layer settings that changed.
- `stratakb add` refuses up front, with exit 2 and reason `local_only`, when `STRATA_LOCAL_ONLY` is set and the embedding settings would send text off the machine, and names the setting; before, it ran and every file failed with `embed_error`.
- Clause-aware chunking: each stored document gets a structure map (migration `09_structure.sql`, table `strata_vectors.document_sections`) of its Markdown, reStructuredText and AsciiDoc headings, numbered headings (`4.3.2`, `7.`, `7(2)(b)`) and keyword headings (`Article 12`, `Section 3`, `Annex II`), found without configuration. A chunk never crosses a section or a PDF page, every piece of a long section keeps the section's path, and each chunk stores it as `clause_path`. Numbered lists inside a clause, dates, amounts and table-of-contents entries are not taken for headings. Existing chunks get a clause path when their file is ingested again.
- Receipts (migration `10_receipts.sql`): a stored record of the quotes behind an answer, with the document version, hash and up to 300 characters of context around each quote, opened with `strata_get_receipt` or the resource `strata://receipts/{receipt_id}`. A receipt shows `v1 -> v2` when its source has changed since and keeps its quote when the source was deleted; document versions a receipt cites are not pruned. The question is always PII-scrubbed. Issuing and opening are audited (`receipt_issue`, `receipt_open`, refusals included) with the receipt id and counts only. Receipts are not readable through the read-only role, and `export-layer` does not carry them. `strata_verify` issues them; extractive answers will too.
- `ANSWER_TOKEN_BUDGET` (default 1500): how many tokens of passages `strata_ask` returns, best first; the first passage always comes back. `top_k` only bounds the search.
- `strata_verify` (viewer): checks a draft answer against the `strata_ask` passages it cites, given as their `ref`s in passage order. Each cited span is read from the store, never from the request. Every quote must appear in the passage it cites (whole words, `...` for an omission), and every number, date, amount, percentage, identifier and clause number outside quotes must appear in a cited passage, compared after normalising formats (`thirty (30) days` matches `30 days`, `EUR 1,000.00` matches `1000 EUR`). A verified draft gets a receipt; otherwise the response lists the flags (up to 50). Drafts are capped at 50,000 characters. The audit entry (`verify`) holds counts and the receipt id, never the draft.
- Clause lookup: `strata_ask` and `strata_search` read clause and section references from the question (`clause 7.2`, `Article 12`, `§ 4`, `Annex II`, a bare `4.3.2` or `7(2)(b)`) and return each matching section first, verbatim from the stored document, with its citation; the same number in several documents gives one passage per document. Questions without a reference search as before.
- `RECEIPT_RETENTION_DAYS` (default 90, `0` keeps them forever): receipts older than this are deleted at startup and every 24 hours, together with document versions only they kept. A run that deleted something is audited as `receipt_prune` by user `system`.
- `AUDIT_STORE_RAW_QUERIES` (default `false`): see Security.
- `stratakb receipt <id>` opens a receipt from the terminal, with the same access rules and audit entry as `strata_get_receipt` (tool name `cli:receipt`). It shows each quote marked `>>> <<<` in its context, with its file, layer, version, clause and status; `--json` prints the tool's response. An unknown or refused id exits 1, an unreachable database exits 3.
- Extractive answers: on a layer with `answer_mode: extractive`, or with `mode: extractive` on the call, `strata_ask` answers with whole sentences of the stored document, chosen by the cross-encoder, each with its citation and a receipt. A clause the question names is quoted without the model. Nothing above the threshold (provisional until the evaluation suite exists) gives `not_found` with no receipt, and a missing model is an error. A span over 2,000 characters is not quoted, and the answer stops at the token budget; a clause the question names with a part left out this way is `partly_found`, with a note saying so. `strata_create_knowledge_layer` accepts `answer_mode`, and the audit entry records the mode.
- The answer contract: the server instructions open with the rules for using an answer (answer only from the passages, cite by id, copy numbers verbatim, verify in grounded mode, show extractive text verbatim, show the receipt id, say when something is not in the documents), and the new MCP prompt `answer_from_documents` walks the same rules. The README gains the section "Answers you can prove", with the flow, the limits and how to open a receipt.
- Layers have `structure_patterns` (migration `11_structure_patterns.sql`), set by a preset: a line starting with a match starts a section labelled by the named group `label`, one level below the open heading or clause. `strata_search` and `strata_ask` look up those identifiers ("show AT-R051"). The SEPA and ISO 20022 presets ship one each.
- Structure from PDF outlines and Word heading styles: a PDF's bookmarks and a Word file's headings (built-in, localized or custom styles and outline levels) now make sections even when the titles carry no numbers. A PDF outline past 10,000 entries or 9 levels is flagged `truncated`.
- `strata_ingest_documents` returns `flagged`, a list of file, reason and count; `stratakb add` rows carry `count`, and its text output prints a Flagged section.
- `import-layer --root <folder>` moves the imported layer to a new folder, so the next `stratakb add` finds its files unchanged.
- The text form of `stratakb receipt` prints one line summing up the verification result that `--json` already carried.
- `strata_verify` returns `nothing_checked`, with a note and no receipt, for a draft with citations but no quote or fact to check. The `verify` audit entry records it as its outcome.
- Each citation in `strata_ask` carries the document's `date` and `date_source`: the front-matter `updated` or `date` key (`front_matter`), else the file's modification time (`file`). Migration `14_document_dates.sql` adds the columns, and layer exports carry them as format 3.
- A document can say in its front matter that it replaces another (`supersedes: failover-2024.md`); citations of the named file then carry `replaced_by`. Migration `15_supersedes.sql` adds the column, and layer exports carry it as format 4.
- Archived files: a layer's `archived_patterns` (`.gitignore` style, at most three wildcards each) label matching citations `"archived": true` on every ask, with no new ingest. Set them with the admin tool `strata_set_archived_patterns` or the preset key `archived_patterns`; both write a `set_archived_patterns` audit entry. Migration `16_archived_patterns.sql` adds the column, and layer exports carry it as format 5; older formats still import.
- `strata_ask` says when part of the answer is missing: a named clause cut to fit the token budget, or left out because more clauses were named than fit, makes a `found` answer `partly_found` with a `note` naming the clause and file; `strata_search` marks such a clause `"cut": true`.
- `strata_ask` checks the names a question asks about (dotted and snake_case names, codes, numbered references such as `PEP 8`) against the passages: some missing makes a `found` answer `partly_found`, none present makes it `not_found` unless a named clause came back, and the `note` lists them.
- `strata_learning_stats` shows each top synonym's layer and `usage_count`.
- A frozen gold set of questions over the Python Enhancement Proposals, with scripts to check and score it, under `evals/`.

### Changed

- Ingesting a folder again now syncs it instead of rebuilding the layer: files with unchanged content are skipped, changed files are replaced, new files are added and files that are gone from that folder are removed, without touching other folders in the layer. `strata_ingest_documents` reports `files_added`, `files_updated`, `files_unchanged` and `files_removed`; pass `replace_all=True` for a full rebuild, for example after changing the layer's chunking or the embedding model.
- A chunk's `source_file` is now the file's path relative to the ingested folder (for example `guides/readme.md`), not its bare name.
- Ingested files are tracked in a new `strata_core.ingested_files` table. The server adds it to an existing database at startup, or on the first ingestion; a layer ingested before this change is rebuilt once on its next ingestion. That first run keeps only the folder it ingests, so ingest every folder of such a layer again (a preset run does this).
- **Breaking:** settings are no longer read from `./.env` in the folder the server starts in. They come from the defaults, then the user-level `config.env` (`%APPDATA%\stratakb\config.env` on Windows, `~/.config/stratakb/config.env` elsewhere), then the file named by `STRATAKB_CONFIG`, then environment variables. The server logs `dotenv_not_read` when it finds a `./.env` it no longer reads. Move your settings to `config.env` or point `STRATAKB_CONFIG` at your file.
- The server answers `initialize` and `tools/list` at once and loads the embedding model in the background (a cold start took 13–20 s before).
- Ingestion no longer fails a run on an empty file or one parser error: secret-named files (such as `client_secret.json` or `secrets.yaml`) are skipped, or removed when they were ingested before; empty files and files with no text are skipped; a file whose parser fails keeps its old chunks while the rest of the run goes on. Every file gets an outcome, and `strata_ingest_documents` returns `files_skipped`. Documents named after secrets but in a document format (for example `credentials.txt` or `secrets.md`) are still ingested, so check what you add.
- The Markdown, HTML and CSV parsers treat empty input as no text instead of a parse error.
- The base schema files `01_init.sql` and `02_learning.sql` moved from `db/` to `src/stratakb/core/sql/`; `db/` keeps only `03_readonly_role.sql`. Pointed at an empty database, the server now creates the StrataKB schemas and the `vector` and `pg_trgm` extensions there instead of failing.
- The README opens with a four-step Quick start in plain words, followed by the reference and a Glossary.
- `stratakb add` and the server share one config source and one entry point; `python -m stratakb` runs the same command.
- A chunk's stored content is now the document's own text. The `[layer > file > section]` prefix is added only to the text that is embedded, so it no longer shows in results and keyword search no longer matches layer or file names. Markdown and HTML sections no longer repeat their parent headings; the heading chain is in the chunk's `section_path` metadata. Chunks ingested before this change keep their prefix until the layer is ingested again.
- `strata_search` no longer turns words in the question into metadata filters.
- `strata_ask` confidence is judged on a meaningful scale: the reranker's relevance probability (0 to 1, the reranker now applies a sigmoid) or, with reranking off, the query/chunk cosine similarity. Before, hybrid scores were divided by the top score, so almost any answer came back `high`. The result reports the `basis` (`rerank` or `similarity`). The thresholds are provisional. Confidence stored for earlier interactions is on the old scale.
- Both search queries run with a 10 s statement timeout.
- A schema update waits at most 30 seconds for a lock another process holds, then stops and names the lock.
- Applying a preset again updates the layer's `display_name`, `description`, `metadata_schema`, `chunk_config`, `routing_patterns` and `answer_mode` from the YAML before the chunks are rebuilt; before, they were set only when the layer was created. A layer with the same name made another way (`stratakb add`, `strata_create_knowledge_layer`, another preset) is refused and left unchanged instead of being cleared; a layer from before origins were recorded is taken over by the preset. A preset without `answer_mode` leaves an existing layer's mode alone, and a `metadata_schema` that is not a mapping is refused when the preset loads.
- The default `DATABASE_URL` uses `127.0.0.1` instead of `localhost`, which can resolve to `::1` and fail with Docker in WSL.
- `vector_store.re_embed_all_layers()` and `re_embed_layer()` read the chunks a batch at a time and embed them before taking the table lock; the lock covers only the resize, the writes and any chunk added in the meantime. Before, they loaded every chunk into memory and held the lock while the model ran.
- Schema update messages say which migration a re-check failed for; the one for 06 names access from a `PUBLIC` grant or a role such as `pg_read_all_data`, which 06 does not revoke. A lock timeout while creating `strata_core.schema_migrations` names that table.
- `strata_ask` merges the results of its rewritten queries by rank (Reciprocal Rank Fusion) instead of dividing each query's scores by its own top score, so chunks no longer tie at 1.0. Every chunk has the same keys (`rerank_score`, `source_file` and `section` included), and a source's `relevance_score` is the score confidence was judged on.
- Chunks added while a re-embed runs are staged again without the lock (up to three passes), so few are left to embed under it. `re_embed_layer()` stops with an error when another process resized the column meanwhile.
- `load_preset` rejects a blank `display_name`.
- `strata_ask` merges the results of its rewritten queries by chunk, not by the first 200 characters of the text, so two different chunks that start the same way both reach the answer.
- Storing a file prunes only that file's old document versions, not the whole layer's.
- Markdown front matter is cut off by one rule, only when its lines look like YAML; a leading `---` break followed by text is kept as text. A byte-order mark no longer hides front matter.
- HTML: the page title is the first `<title>` outside an inline SVG, and SVG titles stay in the text.
- The SQL tools role check at startup runs one query with a 5 s timeout and removes the tools if it fails or stalls.
- The egress report counts an `openai_compatible` query rewrite as outbound only when `QUERY_REWRITE_MODEL` is set, since without a model no rewrite is sent. Model ids in the health report are capped at 20 ids of 100 characters.
- `strata_ask` returns a short answer by default: `status` (`found`, `partly_found` or `not_found`, with a `next_step` for the last two), `mode` (`grounded`) and passages `S1`, `S2`, … each with its exact text, a `ref` to its span of the stored document and its own citation (relative path, page, line range, clause path, layer). The previous shape, with scores, query variants and chunk ids, needs `response_format: "detailed"`, where `status` stays `ok` and the new status is `answer_status`. `strata_feedback` accepts passage ids (`{"S1": "useful"}`) next to chunk ids.
- Opening a receipt gives each quote one `status`, `current`, `changed` or `gone`, in place of the `changed` field. `gone` means the document or its tracked file was removed; `changed` compares the latest version, so a file put back to the cited text reads `current`. Admins may open any receipt. An id that is not `rcpt_` plus 22 URL-safe characters is refused before any lookup and audited as `malformed`, with the id cut to 32 characters.
- When the server or `stratakb add` sets up an empty database, it names it (`host:port/database`, never the user or password) in the log, and `stratakb add` prints it on stderr. It refuses to set up the `postgres` database or a `template*` database; an existing StrataKB schema there keeps working.
- `export-layer` copies every column of the layer, its ingestion runs, tracked files, stored document text, structure map and chunks, in one snapshot; `import-layer` runs in one transaction, gives the documents new ids and stops with "Import failed: nothing was changed." on an error. New export files carry `-- Format: 2`; older files still import, with a warning that the next ingestion rebuilds the layer.
- An invalid `response_format` for `strata_ask` is refused by argument validation as a tool error, and `tools/list` shows the two allowed values.
- Every `query_rewrite_skipped` log event carries `reason`, `provider` and `accepted`.
- `strata_ask` chooses its mode from the passages it returns: any passage from an extractive layer, or a request for extractive, makes the answer extractive, and a result holding only grounded passages stays grounded, so one extractive layer no longer turns every unrouted question extractive. `mode: grounded` still cannot loosen a result with an extractive passage, and the note says so. With no passages, a requested mode is reported as asked, with no note; otherwise the strictest of the layers searched.
- `strata_admin_health`, `strata_search`, `strata_ask`, query rewriting, the query embedding and the raw-query audit setting use the settings the server started with, so a config file edited on a running server takes effect there on restart. Ingestion, presets and the role check still read the settings per call.
- The SEPA and ISO 20022 presets set `answer_mode: grounded`, because their tables and code lists have lines without end marks. Applying them again resets a hand-set extractive layer to grounded and reports it in `layer_changes`.
- Routing patterns and the patterns that find clause references read only the first 2,000 characters of a question; a word cut at that point is dropped. The full question still goes to embedding, full-text search, rewriting, learning and audit.
- `strata_feedback` refuses an unknown chunk rating before storing anything, listing the allowed values, and names any extra it could not store in `not_stored` and `warning`. `strata_reset_learning` trims the layer name, returns the rows deleted and says when there were none. Learning store failures are logged as warnings with the error type.
- `import-layer` refuses a file in a newer or unreadable format, and names another layer that already holds the file's folder before running anything. The prompt, the README and `SECURITY.md` say to import only files you made or trust.
- An `EMBEDDING_BACKEND` other than `local` or `openai` is refused with a message naming the setting. Before, an unknown name with `OPENAI_API_KEY` set sent the texts to OpenAI. A setup such as `EMBEDDING_BACKEND=ollama` with `EMBEDDING_BASE_URL` set must now use `openai`.
- The unused `query_embedding` column is dropped from `strata_learning.interaction_events` (migration `13_drop_query_embedding.sql`). It held only NULLs and would have failed on a model of another size.
- The offline message for the reranking model lists its ways out with one "or", like the local-only message.
- `strata_verify` checks a fact against the passages cited in its sentence, and only a sentence with no citation against all the passages given. A draft with no citations at all is flagged `no citation`; a `[S1]` inside a quote does not count.
- A PDF is flagged `probably_scanned` only when more than half its pages hold an image and under 200 characters of text, instead of on any file averaging under 200 characters per page.
- `strata_verify` accepts an exact clause as long as `strata_ask` returns it for the current `ANSWER_TOKEN_BUDGET`, instead of refusing any span wider than twice the layer's chunk size.
- The server reads `STRATA_USER` and `STRATA_ROLE` once, at startup, for role checks, logs, audit entries, receipts and learning; changing either takes a restart. Before, each tool call reread the config files, so an edit could change the role mid-session. `stratakb receipt` still reads both each time it runs, and `stratakb add` reads only `STRATA_USER`.
- The README describes what works today, for one developer or a small trusted group, and no longer implies a team server; the full tool and settings reference moved to the wiki's Tools and Configuration pages.
- The package description now reads "Knowledge base over the Model Context Protocol whose answers you can check against exact locations in your documents".
- Receipts stored earlier keep `verified`; one with no quotes and no facts checked now opens with a `verification_note` saying nothing was checked, which `stratakb receipt` prints after the Verification line.

### Fixed

- A layer's document and chunk counts are recounted from the database after every ingestion, instead of showing only the last run's numbers.
- Resuming an ingestion no longer skips a file because another file with the same name, in a different folder, was already ingested.
- The keyword leg of hybrid search found almost nothing for natural-language questions, because it required every word of the question. It now matches any word of the question (stemmed, with stopwords dropped by PostgreSQL), keeps the best-ranked matches when more match than it returns, and keeps the strict web-search syntax for queries with quoted phrases, `OR` or `-exclusions`.
- Implicit signals (rephrasing, layer switches) were lost whenever the previous query had results, because stored results came back as JSON text.
- Layer switches are compared with the layers routing picked for the previous query, not with the layers it searched.
- Synonym mining pairs a rephrased question with the question just before it, not with every earlier question in the session.
- Interactions record their real response time instead of 0, and the promoter reports how many rewrites it decayed.
- `strata_feedback` rejects an unknown `interaction_id` instead of reporting success.
- The query and routing caches are cleared when any process changes a layer (checked at most every 2 s); before, searches could serve results up to 10 minutes old.
- The CI and release workflows pin `astral-sh/setup-uv` to a tag that exists.
- The embedding and reranking models are downloaded when they are not cached. Before, the server switched Hugging Face to offline mode when it loaded, so a new install could not ingest, search or ask until the models were downloaded by hand. A cached model still loads without contacting Hugging Face, and with `STRATA_LOCAL_ONLY=true` nothing is downloaded.
- Each layer is chunked with its own `chunk_size` and `chunk_overlap`. Before, the stored settings came back from the database as text and every layer was chunked at 1000/200. Layer listings return `chunk_config` and `metadata_schema` as objects and `routing_patterns` as a list.
- `vector_store.re_embed_layer()` no longer resizes the vector column that every layer shares, which left the other layers unsearchable and locked the whole table. It refuses a new size and points at `re_embed_all_layers()`; the startup check's message says the same.
- A half-built schema (`01_init.sql` applied without `02_learning.sql`) is repaired instead of failing the update. A user without `USAGE` on the StrataKB schemas is told which privilege is missing, instead of being sent to a schema file. Migration 06 is no longer recorded when the database user could not revoke the grants it removes.
- `strata_search` interactions store a confidence judged on the query/chunk similarity, with its level. Before, they stored the top fused score, which is always 1.0, and no level, so the learning loop never learned from searches. `strata_search` results now carry each chunk's `similarity`.
- A CSV file over 10,000 rows was cut short without a message. It is now stored for its first 10,000 rows and reported as flagged (`truncated`), and the log says how many rows were left out.
- A CSV row with fewer fields than the header failed the whole file. It is now stored with the values it has, and a row with more fields keeps the extra values, labelled by position (`Column 4`).
- `stratakb db up` and `db down` print one line and exit 3 on an unexpected error instead of a stack trace, and recognize Docker Desktop's "Ports are not available" message as a port in use.
- `stratakb add --max-file-size inf` crashed; it is now a usage error (exit 2), like `0`, a negative value or `nan`, and the command refuses them before it connects to the database.
- CSV columns with an empty header name are labelled `Column N`, and a repeated name gets a suffix (`Name (2)`). Before, the empty one gave a line with no label and the earlier of two same-named columns was lost. Header names are trimmed.
- Markdown headings inside fenced code blocks no longer split a section, and an HTML page's `<title>` is used for the section path but no longer repeated in the text.
- Applying a preset to a layer with no origin claims it in the same guarded update that writes its settings; an origin another process wrote in between is no longer overwritten, and a failed write no longer leaves the layer half-updated.
- A failed cleanup of the re-embed staging table no longer hides the error that caused it.
- When a schema update's read-only grants (06) are not in place although the connecting user owns the schema, the message names the likely cause instead of asking to run as the owner.
- Concurrent or cancelled first calls no longer create extra database connection pools or leave a half-made one open.
- A chunk without an embedding no longer makes vector search fail; it is left out of the similarity ranking and can still be found by keyword.
- Two concurrent stores of the same file no longer fail on the version number.
- Requests to a custom OpenAI-compatible endpoint (`EMBEDDING_BASE_URL`, `QUERY_REWRITE_BASE_URL`) no longer carry the `OpenAI-Organization` and `OpenAI-Project` headers the SDK takes from `OPENAI_ORG_ID` and `OPENAI_PROJECT_ID`.
- A keyless OpenAI-compatible endpoint (a default Ollama, llama.cpp or vLLM on localhost) works for embeddings and query rewriting: with no key configured the request carries no `Authorization` header instead of failing on a missing key, and never falls back to `OPENAI_API_KEY` or `OPENAI_ADMIN_KEY`. When such an endpoint answers 401, `strata_admin_health` names the key setting that is empty.
- Filtered vector search could return far fewer results than asked for: the HNSW index gave at most 40 candidates before the layer or metadata filter applied. On pgvector 0.8 or later each search now turns on iterative index scans (`hnsw.iterative_scan = relaxed_order`); older versions keep the previous behaviour and log `hnsw_iterative_scan_unavailable` once.
- `strata_ask`: feedback on passage `S21` and later was refused, because only 20 results were stored; up to 50 are now. Confidence is judged on the reranked chunks before packing, so an answer whose budget keeps one large passage can still be `high`. The token budget counts each passage's id, ref and citation, not only its text.
- A heading followed directly by its first subsection ("7. Termination" then "7.1 …") is no longer stored as a chunk holding only the heading line. A loose `1.` list in a Markdown file is no longer taken for a section, front matter is no longer read as a reStructuredText heading, and table-of-contents lines are skipped for extra patterns too. Parsing, the structure map and chunking run off the event loop.
- Receipts: a source file removed from its folder no longer reads as unchanged, a deleted layer no longer locks out everyone but the issuer, and a receipt prune running during `strata_verify` no longer fails with a raw foreign-key error or deletes a document the new receipt cites; a pruned document gives an "Unknown document" error instead. Quotes and their context are read in SQL, not by loading each document's whole text.
- `strata_reset_learning` runs as one transaction. A reset that failed in the database returned `ok` and was audited as done, and could leave some tables cleared; it now returns an error and writes no audit entry. An empty or blank `layer` is refused instead of resetting everything. The `strata_feedback` audit entry names only the extra signals that were stored.
- Markdown front matter with spaced keys (`date created: 2024`, as Obsidian writes them) is recognised instead of being indexed as text. An SVG `<title>` inside an HTML heading no longer joins the heading text.
- A model setting that names a folder (`EMBEDDING_MODEL=C:\models\mpnet`) loads from that folder only; a missing folder or one without a model fails with a message naming the setting and the folder, instead of a download hint or an online retry. With `HF_HUB_OFFLINE` or `TRANSFORMERS_OFFLINE` set, a missing model names that variable.
- The learning tracker uses the settings the server was built with, not the environment's.
- An ingest running next to a file removal, a layer clear or receipt retention could fail with a raw database error: a pruned document version gave a foreign-key violation reported as `embed_error`, and a clear could deadlock with an ingest or a removal. File rows are now locked in one order.
- Receipt retention could deadlock with `strata_verify` when a receipt cited two layers. All cited layers are now swept in one statement.
- An unclosed `<title>` inside an HTML heading's `<svg>` swallowed the rest of the page. It now ends at `</svg>` or at the end of the heading, as in browsers.
- An OpenAPI file whose schema summaries leave properties out is flagged `truncated`, with the count. Before, those properties were unsearchable without a hint.
- Query rewriting closes its HTTP client after each call, which used to stay open.
- The local database readiness wait, the schema check and the SQL tools role check open their single connection with a deadline; a stalled role check had no connect timeout.
- An explicit heading that is only a clause number or keyword id (`Article 6`, `7.`) no longer doubles the number in its section name, and tables in a Word file stay in their section instead of moving after all paragraphs.
- Learning no longer mines synonyms from unrelated questions that shared common words: similarity uses content terms only and must reach 0.3, a pair needs exactly one term unique to the first question and two sightings, and mined synonyms are stored at confidence 0.7. Rows stored at 0.6 stop being applied and are deleted on the next promoter run, and a rerun no longer duplicates rows with no layer.
- Deleting a layer during an ingest of it could deadlock. `delete_layer`, `clear_layer` and file removal now lock file rows in the same order as an ingest.
- The gold set scorer turns learning off itself, stops at the first failed question or a missing layer, and writes its output only for a finished run; the checker exits non-zero on problems.

### Security

- `strata_db_query` and `strata_db_explain` run each statement in a read-only transaction that is always rolled back, so `SELECT … INTO`, writing functions and `set_config()` no longer take effect. The statement timeout is now transaction-local instead of sticking to the pooled connection, and rows are fetched through a cursor up to the 1,000-row cap instead of in full.
- The SQL tools are registered only when `READONLY_DATABASE_URL` is set, and are removed at startup when that role is a superuser, a member of one, or holds a server-file or signal role. They no longer fall back to the owner role.
- The `strata_readonly` role may read only `knowledge_layers`, `ingestion_runs`, `ingested_files`, `chunks` and `documents` (migration `08_readonly_documents.sql`), not the audit log, users or the learning schema. Migration `06_readonly_grants.sql` narrows existing installs at startup.
- Locked dependencies upgraded to patched releases for all 124 open advisories (among them certifi, PyJWT, AnyIO, pypdf, transformers, urllib3, cryptography, starlette and python-multipart). Some transitive packages move a major version: filelock 4, cryptography 50, soupsieve 4 and huggingface-hub 2.
- File listing through git passes `core.fsmonitor=false`, so a crafted `.git/config` in an added folder cannot run a command.
- Ingest errors returned to the caller and stored in `ingestion_runs.error_log` name the file by its path relative to the ingested folder, never the absolute path (which can hold the user's name), and are cut to 300 characters. The embed and store failure logs record the error type only, not the exception text.
- The PDF and Word parse-error logs and the embedding API error log record the error type only; a corrupt `.docx` put its absolute path in the log. The ingested folder is replaced in errors only at a path boundary (`/data/docs` no longer rewrites `/data/docs2/x`), and case-insensitively where the filesystem is.
- The audit entries of `strata_search` and `strata_ask` store the question scrubbed of IBANs, BICs and account numbers, like the learning store. `AUDIT_STORE_RAW_QUERIES=true` keeps it as written; it is independent of `LEARNING_STORE_RAW_QUERIES`.
- The text output of `stratakb receipt` shows control and other non-printable characters from documents, questions and drafts as `\xNN` or `\uNNNN` escapes, so a document cannot send terminal escape sequences to whoever opens the receipt.
- Routing patterns that repeat a repeated part are refused when a layer is created or updated and when a preset is loaded, and skipped with a warning at search time for layers already holding one, so a badly backtracking pattern cannot stall a search.
- `stratakb receipt --json`, its JSON error form and `stratakb add --json` write DEL, C1 controls and bidi overrides as `\uXXXX` escapes, so a document quote or file name cannot drive the terminal; the output stays valid JSON. The text report of `stratakb add` and the refusal hints now escape them too, each entry on one line.
- The `creating_db_pool` log shows only host and port. Before, a `DATABASE_URL` with the password in its query string (`?user=…&password=…`) put the password in the log.
- Structure patterns already stored in a layer (from an import, a restore or an older version) that do not compile or repeat a repeated part are now skipped with an `unsafe_structure_pattern` warning in the clause lookup and at ingest, as routing patterns already were at search time, and `import-layer` drops such structure and routing patterns, naming each. The `label` group a question runs is checked too, so a pattern that only looks safe as stored cannot stall a search.
